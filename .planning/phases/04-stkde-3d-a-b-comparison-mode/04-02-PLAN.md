<context>
`computeSliceKde` currently computes a complete `Float32Array` and then discards it while emitting sparse normalized `cells`. Add the raw field to the existing result without changing the meaning or threshold behavior of `cells`; existing consumers must continue to compile. The comparison field is small and client-local. Use one absolute maximum for both selected fields and a stable non-zero fallback domain for all-zero differences. Missing fields and grid mismatches are invalid comparison inputs, not neutral data.

Preserve `STKDE_INTENSITY_STOPS`, `LEGACY_STKDE_INTENSITY_STOPS`, and their existing helpers for absolute views. Add a separate signed stop list using the UI-SPEC semantics: `#175CD3`/blue for B higher, `#F4F1EB`/neutral for zero, and `#B42318`/red for A higher. Do not encode signed meaning through the existing cream-to-red sequential palette.
</context>
