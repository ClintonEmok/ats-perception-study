# Quick Task 260806-k90 Summary

**The dashboard-demo timeline, cube, and map now share one source-consistent active slice: clicking or keyboard-activating a timeline slice bar selects the same slice the cube highlights, cube playback/index changes reconcile back to the timeline, and the map emphasizes in-slice events while retaining out-of-slice events as subdued context.**

## Accomplishments

- `DualTimelineSurface` gained an optional `onSliceClick` callback attached only to the real `orderedSliceGeometries` bars: each rendered slice bar is now mouse-clickable and keyboard-accessible (Enter/Space) with a button role, accurate `aria-label`, `aria-pressed` active state, and pointer cursor; pending draft/manual preview geometry remains non-interactive (`pointerEvents="none"`, no role).
- `DemoDualTimeline` implements the callback with `setActiveSlice` (slice-domain store) plus `setActiveSliceIndex` (coordination store), resolving the coordination index from a canonical visible range-slice ordering (chronological epoch start/end with stable id tie-breaking — the same ordering the cube uses) rather than from the visually re-sorted `orderedSliceGeometries`. Point slices set index `-1` instead of an unrelated cube index.
- `Demo3dSpatialView` completes cube-to-timeline reconciliation: `onActiveIndexChange` now resolves the cube runtime index back to the canonical counted-slice source id and writes `setActiveSlice` alongside `setActiveSliceIndex`; the initial-load and clamped-index effects also set the timeline `activeSliceId` so the timeline is never left null or stale after the cube initializes or its slice list changes. Existing `onSliceSelect`, `onSliceResize`, and canvas-missed behavior are preserved.
- The dashboard map highlights rather than filters: `DemoMapVisualization` passes the active-slice epoch range as an explicit `sliceHighlightRange` (no longer a data-filter `sliceTimeRange`), `MapVisualization` keeps the regular viewport/filter records available to the event layer, and `MapEventLayer` computes an `inActiveSlice` GeoJSON property from epoch timestamps (records direct, columns via `timestampSec`, data path via a unit-aware milliseconds/normalized/epoch conversion) and uses Maplibre paint expressions to enlarge/brighten/ring matching points while subduing context points to ~0.22 opacity. Existing hover styling, category colors, and the no-highlight appearance are preserved.

## Decisions Made

- The coordination index for a clicked timeline slice must come from the canonical visible range-slice ordering shared with the cube, never from the stacking-order `orderedSliceGeometries`, so the timeline and cube always agree on the same slice.
- Point slices are not cube-compatible and therefore map to coordination index `-1` (clearing the cube's active slice) rather than a fabricated cube index.
- The cube is the index source of truth for playback/scrubbing; each runtime index change is translated back through the source id so the timeline highlight tracks cube navigation and never shows a null or stale slice after initialization or slice-list changes.
- The dashboard map keeps all viewport/filter events in the layer and computes highlight via a per-feature `inActiveSlice` property, avoiding a second data fetch and never hiding out-of-slice context points.
