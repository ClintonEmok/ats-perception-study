## Cross-phase integration

All wiring checked and passing:

- Phase 87 → Phase 89: Convex mutations `startSession`, `startTrial`, `recordTrialOnset`, `recordTrialResponse`, `completeTrial`, `submitQuestionnaire` are called from `useExperimentStore` actions.
- Phase 87 → Phase 90: counterbalancing (`assignConditionOrder`) is consumed by `startSession`; base datasets (`getUniformVariants` / `getAtsVariants`) are consumed by `ParticipantFlow.pickPracticeVariant` and `pickExperimentalVariant`.
- Phase 88 → Phase 89: `useStimulusTiming` wraps `createTimingSource`; `TimelineStimulus` is mounted inside `TrialRunner`; both are children of `ParticipantFlow`.
- Phase 89 → Phase 90: export helpers read `useExperimentStore.responses` and `useExperimentStore.questionnaire`; import guard prevents any prototype leakage.
- Phase 90 → deployment: `vercel.json` + `convex.json` + `.env.example` + `docs/DEPLOYMENT.md` + `docs/PILOT.md` form a complete deploy-and-pilot runbook.

## E2E flows

- **Anonymous participant flow**: `/experiment` page → ConvexClientProvider → ParticipantFlow → useExperimentStore FSM → practice → blocks → questionnaire → debrief. Wired end-to-end with the noopWrites fallback so the page renders and tests can simulate a full session.
- **Data write flow**: onset → response → complete → session close. Each step fires a Convex mutation via the `convexWrites` interface. Two-phase write guaranteed by the store and runner.
- **Export flow**: `exportSessionData` reads from the store, produces CSV or JSON. Researcher can call it from the browser console or from a future admin page.
